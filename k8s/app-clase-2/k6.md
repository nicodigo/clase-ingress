Asumiendo que ya tenés el cluster de GKE configurado y la API desplegada, son tres pasos:
1. Verificar que la API esté corriendo
kubectl get pods -n load-api
kubectl get svc -n load-api
Los pods deben estar en estado Running antes de lanzar el test.
2. Aplicar el manifest
kubectl apply -f k6-load-test.yaml
Esto crea el ConfigMap con el script y lanza el Job.
3. Seguir los logs en tiempo real
kubectl logs -n load-api -f job/k6-load-test

Comandos útiles durante el test
# Ver el estado del Job (Running / Complete / Failed)
kubectl get job -n load-api k6-load-test

# Ver el pod que ejecuta k6
kubectl get pods -n load-api -l job-name=k6-load-test

# Ver si el HPA está escalando los pods de la API
kubectl get hpa -n load-api --watch

# Ver cuántos pods de la API hay en cada momento
kubectl get pods -n load-api --watch

Si necesitás relanzar el test
El Job no se puede volver a ejecutar directamente, hay que borrarlo y recrearlo:
kubectl delete job k6-load-test -n load-api
kubectl apply -f k6-load-test.yaml

Resultado final
Cuando el Job termina, los logs muestran el resumen completo de k6 con las métricas y si los thresholds se cumplieron o no:
✓ health: status 200
✓ cpu: status 200
✗ cpu_latency_ms................: p(95)=9234ms  ← threshold superado

Job failed   ← exit code 99 si algún threshold falló
Job complete ← exit code 0 si todo pasó
El Job se autoeliminará 5 minutos después de terminar (por el ttlSecondsAfterFinished: 300), pero los logs quedan disponibles hasta ese momento.
